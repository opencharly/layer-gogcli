# 2026.246.0100 — fix: gogcli module path (steipete -> openclaw)

## Summary

The upstream `gog` module renamed from `github.com/steipete/gogcli` to
`github.com/openclaw/gogcli`. The candy's `go install` build step still used the
old path, so `go install github.com/steipete/gogcli/cmd/gog@latest` failed with a
module-path mismatch (`module declares its path as: github.com/openclaw/gogcli`).
This broke every box composing `layer-gogcli` (the openclaw-full metalayer among
them) at build time.

Fix: the build step and description now use `github.com/openclaw/gogcli`. The
candy's own CalVer moves because changed content must ship under a new version.

## How tested

```
$ /tmp/charly-ci/bin/charly box validate
exit 0
```

Run with the charly version this repo's own `deploy.yml` clones and builds
(v2026.238.1242). The runtime path (the `go install` of the renamed module) is
exercised by the consuming `check-openclaw-full-pod` bed in the distro-cachyos
repo, which builds the openclaw-full image composing this candy — that R10 evidence
lands with the distro-cachyos PR.
